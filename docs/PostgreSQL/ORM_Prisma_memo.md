## Getting Started

To start a new project with Prisma and PostgreSQL, follow these steps (based on the official Quickstart).

### 1. Create a new project

Create a project directory and navigate into it:

```bash
mkdir prisma-project
cd prisma-project
```

Initialise a TypeScript project:

```bash
bun init
```

### 2. Install required dependencies

Prisma now uses **Driver Adapters** for better performance and serverless compatibility.

```bash
bun add -d prisma @types/pg @types/express
bun add @prisma/client @prisma/adapter-pg pg express
```

**Packages:**

- `prisma`: The CLI tool for running commands like `prisma init`, `prisma migrate`, and `prisma generate`.
- `@prisma/client`: The Prisma Client library for querying your database.
- `@prisma/adapter-pg`: The node-postgres driver adapter that connects Prisma Client to your database.
- `pg`: The node-postgres database driver.
- `@types/pg`: TypeScript type definitions for node-postgres.

### 3. Initialise Prisma ORM

You can now invoke the Prisma CLI by prefixing it with `bun`:
```bash
bun prisma
```

Next, set up your Prisma ORM project by creating your Prisma Schema file with the following command:

```bash
bun prisma init --datasource-provider postgresql
```

This command does a few things:

- Creates a `prisma/` directory with a `schema.prisma` file containing your database connection and schema models.
- Creates a `.env` file in the root directory for environment variables.
- Creates a `prisma.config.ts` file for Prisma configuration.

### Basic File Structure

This is the expanded file structure of the project. We group database logic in `src/db`, mirroring the Drizzle layout for consistency.

> **Note:** Unlike Drizzle, Prisma keeps its schema and seed script in a dedicated `prisma` folder by convention, while the client instance and factories live in `src`.

```text
📦 <project root>
 ├ 📂 prisma
 │   ├ 📂 migrations      # SQL migration files generated by Prisma Migrate
 │   ├ 📜 schema.prisma   # Schema definition
 │   └ 📜 seed.ts         # Script to populate the database with initial data
 ├ 📂 src
 │   ├ 📂 db
 │   │  ├ 📜 index.ts     # Prisma Client Instance (with Adapter)
 │   │  └ 📜 factory.ts   # Data generators (Faker)
 │   └ 📜 index.ts        # App entry point
 ├ 📜 .env
 ├ 📜 prisma.config.ts    # Prisma Configuration
 ├ 📜 package.json
 └ 📜 tsconfig.json
```

#### Prisma Config (`prisma.config.ts`):

The generated `prisma.config.ts` file looks similar to this:

```typescript
// This file was generated by Prisma, and assumes you run Prisma commands using `bun --bun run prisma [command]`.
import { defineConfig, env } from "prisma/config";

export default defineConfig({
  schema: "prisma/schema.prisma",
  migrations: {
    path: "prisma/migrations",
  },
  datasource: {
    url: env("DATABASE_URL"),
  },
});
```

> [!TIP] **Runtime Selection Guidance**
If you have **Node.js installed** on your system, use `bun --bun prisma <command>` to ensure Node is never touched. This forces the Bun runtime even if a script's "shebang" (the first line of the code) explicitly requests `node`.
> 
If you **do not have Node installed**, `bun prisma <command>` will work fine because Bun automatically detects the missing dependency and aliases itself to the `node` command for that specific process, making it the only available provider.

#### Schema (`prisma/schema.prisma`)

The generated schema uses the ESM-first prisma-client generator with a custom output path:

```prisma
// This is your Prisma schema file,
// learn more about it in the docs: https://pris.ly/d/prisma-schema

// Looking for ways to speed up your queries, or scale easily with your serverless or edge functions?
// Try Prisma Accelerate: https://pris.ly/cli/accelerate-init

generator client {
  provider = "prisma-client"
  output   = "../generated/prisma"
}

datasource db {
  provider = "postgresql"
}
```

#### Environment Variables (`.env`)

Update your `.env` file with your PostgreSQL connection string:

```env
DATABASE_URL="postgresql://username:password@localhost:5432/mydb?schema=public"
```

Replace the placeholders with your actual database credentials:

- `username`: Your PostgreSQL username
- `password`: Your PostgreSQL password
- `localhost:5432`: Your PostgreSQL host and port
- `mydb`: Your database name

### 4. Define Data Model

Add the following models to your `prisma/schema.prisma` file to define sample `Product` and `Category` tables:

```prisma
model Product {
  id          Int      @id @default(autoincrement())
  name        String
  price       Float
  category_id Int
  category    Category @relation(fields: [category_id], references: [id])
}

model Category {
  id       Int       @id @default(autoincrement())
  name     String
  products Product[]
}
```

### 5. Create and Apply First Migration

Run the following command to create your first migration and apply it to the database:

```bash
bun prisma migrate dev --name init
```

This command will:
1. Generate a SQL migration file in `prisma/migrations`.
2. Execute the SQL against the database.

Now run the following command to generate the Prisma Client:

```bash
bun prisma generate
```

### 6. Instantiate Prisma Client (`db/index.ts`)

Initialise the client using the `pg` driver adapter.

```typescript
import { PrismaPg } from '@prisma/adapter-pg'
import { PrismaClient } from '../generated/prisma/client'

const connectionString = `${process.env.DATABASE_URL}`

const adapter = new PrismaPg({ connectionString })
const prisma = new PrismaClient({ adapter })

export { prisma }
```


### 7. Seed the Database

Seeding allows you to populate your database with initial data for development or testing. In Prisma 7, the seed command is managed via `prisma.config.ts` rather than `package.json`.

#### Update Prisma Config (`prisma.config.ts`)

Add the `seed` property to the `migrations` object. This tells the Prisma CLI which command to execute when you run `db seed`.

```typescript
export default defineConfig({
  schema: "prisma/schema.prisma",
  migrations: {
    path: "prisma/migrations",
    seed: "bun run prisma/seed.ts", // Use bun to execute the TS file directly
  },
  datasource: {
    url: env("DATABASE_URL"),
  },
});

```

### 8. Write your first query

```typescript
import express from "express";
import type { Express, Request, Response } from "express";
import { prisma } from './db/index.ts';

const app: Express = express();
const port = process.env.PORT || 3000;

app.use(express.json());

// 1. Get all products with their categories
app.get("/products", async (req: Request, res: Response) => {
  const categoryName = req.query.category as string;

  try {
    const products = await prisma.product.findMany({
      where: categoryName ? {
        category: {
          name: {
            equals: categoryName,
            mode: 'insensitive' // Optional: Makes search case-insensitive
          }
        }
      } : {},
      include: { 
        category: true 
      }
    });
    
    res.json(products);
  } catch (error) {
    res.status(500).json({ error: "Failed to fetch products" });
  }
});

// 2. Create a new product
app.post("/products", async (req: Request, res: Response) => {
  const { name, price, category_id } = req.body;
  try {
    const product = await prisma.product.create({
      data: {
        name,
        price: parseFloat(price),
        category_id: parseInt(category_id),
      },
    });
    res.status(201).json(product);
  } catch (error) {
    res.status(400).json({ error: "Failed to create product" });
  }
});

// 3. Get all categories
app.get("/categories", async (req: Request, res: Response) => {
  try {
    const categories = await prisma.category.findMany();
    res.json(categories);
  } catch (error) {
    res.status(500).json({ error: "Failed to fetch categories" });
  }
});

app.listen(port, () => {
  console.log(`[server]: Server is running at http://localhost:${port}`);
});
```
